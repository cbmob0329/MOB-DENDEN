# MOB CHILL LIFE — コインプッシャー 3D アセット

実際の Blender メッシュと glTF 2.0（GLB）の素材集です。ゲーム本体への組み込み、物理エンジン設定、当たり判定の接続、報酬ロジックはまだ行っていません。

## 開くファイル

- `../source/MOB_CHILL_LIFE_coin_pusher.blend`：赤／金と青／金の2台、可動プッシャー、ガラス、物理用補助オブジェクト、コイン展示、照明・カメラ。
- `../gameassets/exports/cabinet_red.glb` / `cabinet_blue.glb`：単体筐体。原点は床中央。展示コインを除いたゲーム組み込み用。
- `../gameassets/exports/two_cabinets.glb`：2台を並べた展示シーン。左右 X=-0.70 / +0.70m。展示コインを含みます。
- `../gameassets/exports/gold_sunglasses_mascot.glb`：上部の金色・丸サングラスマスコット単体。
- `../source/prize_library.blend`：コイン、M/O/B各3色、どら焼き、コイン袋、木箱、金箱。
- `../source/slot_symbols.blend` と `../gameassets/symbols/`：全10種のリール図柄。GLBに加え、透過PNGも収録。
- `../previews/`：実際の3Dシーンからのレンダリング。全体、機構カット、正面、側面、上面、図柄、景品。
- `assets_manifest.json`：寸法、座標、アンカー、可動距離、推奨質量、三角形数。

## 座標とインポート

単位はメートル、Blenderでは Zが上・-Yが正面・+Xが右です。GLB書き出しでは標準変換により Yが上・+Zが正面になります。1.0倍で読み込んでください。筐体全高は上のコイン込みで約2.8mです。

Blender 4.3以降で `.blend` を開けます。Unity / Godot / Three.js 等には `.glb` を読み込み、用途に合わせてエンジン側でマテリアルと物理を設定してください。

## 分離された構造

筐体外装、側面ガラス、上面ガラス、固定フィールド、左右のコインシュート、移動プッシャー、リール3窓、ストックランプ5個、L/Rボタン、前方落下縁、回収ボウル、上部マスコットは別オブジェクトです。

`PusherPlate_MOVING` はY方向に0.115m往復します。`Pusher_Reciprocate_2s` は1〜81フレーム、40fps、2秒のデモ動作です。ゲームではループ再生し、プッシャーをキネマティック剛体として同じ変位に同期させます。`COL_Pusher` は可動メッシュに親子付けされています。

スロット穴は絵ではなく、固定フィールドのメッシュに実際に空いた開口です。Blender座標で X=-0.085〜+0.085、Y=-0.24〜-0.14m。穴の周囲を4枚の固定フィールドで構成し、下にトンネル壁とセンサー用補助メッシュがあります。ここを横切る全面ボックスコライダーは作らないでください。

## 物理接続の要点

- `COL_*` は補助形状です。エクスポート時は透明マテリアルで不可視化されています。エンジン側で必ずレンダラーを無効にし、役割に応じたコライダー／トリガーを追加してください。
- `COL_CabinetBounds` は配置・広域判定のための外接箱です。内部を塞ぐソリッドコライダーとして使用しないでください。
- 固定フィールドは各メッシュから静的コライダーを作成し、穴を保ちます。
- `COL_SlotTrigger`：コインが穴に入ったとき「コイン1枚分＋スピン1回」を1度だけ処理する接続先。
- `COL_FrontWinTrigger`：前方落下した景品・コインの回収判定。
- 入力は `Anchor_Input_L` / `R`、シュート出口は `Anchor_ChuteExit_L` / `R`。コインの円柱軸をX方向に向けると、YZ面内を転がして投入できます。
- コインは半径0.026m、厚さ0.005m。物理のサブステップ、連続衝突判定、摩擦、反発を実機で調整してください。狭い段差への引っ掛かり・すり抜けはエンジンごとの検証が必要です。
- M/O/B景品の報酬100、どら焼き80はオブジェクトのカスタムプロパティと仕様上の値です。加算処理はゲーム側で実装します。
- チェストの蓋は後端ヒンジの別パーツです。蓋用アンカーのローカルXを約-105度回すと開きます。

## 図柄

赤MOB・青MOB・緑MOB・どら焼き・7・Denden・Pink・コイン袋・木箱・金箱の10種。

DendenとPinkは、確認済みの提供画像をUVトリミングしたポートレートです。新しいキャラクターデザインを捏造していません。これら2種はテクスチャ付き平面、他8種は3Dメッシュです。元画像はGLB / blendに埋め込まれており、外部画像への参照切れを防いでいます。

上の大きな画面はガイドどおり無地の黒です。ゲームUIを表示する位置に `Anchor_UpperDisplay`、リール表示位置に `Anchor_Reel_1`〜`3` があります。初期筐体にある7はデモ用メッシュで、ゲーム用の表示へ差し替えてください。

## 軽量化とレンダリング

筐体は1台16,360三角形（展示コイン・物理補助を除く）。コインはMOBの軽い立体模様込み148三角形。各景品は約204〜1,172三角形です。コインは共有メッシュのインスタンス利用を推奨します。2台の筐体もBlenderではメッシュを共有し、色マテリアルだけを切り替えています。

透明ガラスは独立マテリアルです。モバイルで負荷や描画順が問題になる場合は、薄いアルファ表示へ変更するか上面だけ非表示にできます。実装前の自動LOD・リジッドボディ・スピン制御・賞品抽選・音声は含みません。

## 再生成

`../source/scripts/build_assets.py` → `../source/scripts/finalize_assets.py` → `../source/scripts/fix_front_clearance.py` → `../source/scripts/verify_geometry.py` → `../source/scripts/normalize_delivery.py` の順にBlenderバックグラウンドで実行します。景品の形状は `../source/scripts/prizes.py`、図柄は `../source/scripts/build_symbols.py` と `../source/scripts/render_symbol_icons.py`。キャラクター元画像の再生成時パスは実行環境に合わせて変更してください。納品済みGLB / blendの利用には元パスは不要です。

物理の推奨初期値：コイン0.007kg、文字景品0.018kg、軽いどら焼き0.0056kg（コインの0.8倍）。いずれも未検証の調整出発点です。スクリプトは制作ソースであり、パス調整なしのワンクリック再生成を保証しません。

スロットへの景品誤落下に備え、景品ではコイン加算・スピンを発生させず、景品ID・所有者・報酬値を保持したまま `Anchor_PrizeRecovery`（0.25, -0.34, 0.88）周辺の空きを確認して1回だけ復帰させる実装を想定しています。空きがない場合は消去せず、見える形で保留してください。開口自体は通常コインが通過する寸法を維持しています。

形状検証では固定フィールドと支持デッキを通る穴中央のレイが遮られないことを確認しています。GLBの再読み込みでノード、アンカー、透明補助材質とプッシャーの親子関係を確認済みです。これはゲームの物理・抽選ロジックの動作検証とは別です。

単体GLBは赤・青とも同じ標準ノード名（例：PusherPlate_MOVING、Anchor_PrizeRecovery）です。2台入りGLBとメインBlenderファイルでは赤は標準名、青は _Blue 接尾辞です。最終図柄色とクリーム背景のシートは final_materials_symbols.py、ノイズを抑えた確認画像は render_clean_previews.py で生成しています。
